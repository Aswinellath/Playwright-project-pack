# new_1month_pw

A Playwright + TypeScript test automation project that covers UI testing with the Page Object Model, data-driven testing, and REST API testing.

## Tech stack

- [Playwright Test](https://playwright.dev/) (`@playwright/test`)
- TypeScript
- [Faker](https://fakerjs.dev/) (`@faker-js/faker`) for random test data
- GitHub Actions for CI

## Applications under test

| Application | Type | Used in |
|---|---|---|
| [SauceDemo](https://www.saucedemo.com/) | UI | Login, products, cart, checkout tests |
| [DemoQA practice form](https://demoqa.com/automation-practice-form) | UI | Form handling (`Day3.spec.ts`) |
| [JSONPlaceholder](https://jsonplaceholder.typicode.com/) | API | `tests/api/jsonplaceholder.spec.ts` |
| [FakeStoreAPI](https://fakestoreapi.com/) | API | `tests/api/fakerstoreapi.spec.ts` |

## What is covered

**UI tests (SauceDemo)**
- Login: valid, invalid, and locked-out users; clearing the error message
- Products: listing, adding and removing items, sorting by name and price
- Cart: item quantities and descriptions
- End-to-end checkout: single product, multiple products, empty cart

**Data-driven tests**
- Login with multiple users from an inline data table
- Adding products read from a JSON file
- Checkout with random customer data generated by Faker

**API tests**
- JSONPlaceholder: GET, POST, PUT and DELETE on posts
- FakeStoreAPI: products, categories, carts, adding a product, user login

## Getting started

Prerequisites: [Node.js](https://nodejs.org/) (LTS).

```bash
npm ci
npx playwright install --with-deps
```

## Running tests

```bash
# Run all tests (Chromium and Firefox)
npx playwright test

# Run one file
npx playwright test tests/Day5e2e-Checkout.spec.ts

# Run only the API tests
npx playwright test tests/api

# Run in one browser
npx playwright test --project=chromium

# Run with the browser visible
npx playwright test --headed

# Open the interactive UI mode
npx playwright test --ui
```

## Reports

Tests produce an HTML report. Open the latest one with:

```bash
npx playwright show-report
```

Traces are recorded on the first retry of a failed test and can be viewed from the report.

## Configuration

See `playwright.config.ts`:
- Test directory: `./tests`
- Browsers: Chromium and Firefox
- Runs fully in parallel locally; on CI it uses 1 worker and 2 retries

## Continuous integration

The workflow lives at the root of the repository in `.github/workflows/new_1month_pw.yml` (GitHub only runs workflows from there). It runs whenever files in `new_1month_pw/` change on `main`/`master`, on pull requests, or manually from the Actions tab. It installs dependencies and browsers, runs the full suite inside `new_1month_pw/`, and uploads the HTML report as a build artifact (kept for 30 days).

> Note: the credentials in these tests are the public demo accounts published by SauceDemo and FakeStoreAPI.
